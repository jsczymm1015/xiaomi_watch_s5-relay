# 手机上使用

仅适用于小米 Watch S5 **41mm / Q63**。先安装 [小米手表中转.apk（ZIP 内中文文件名）](https://github.com/jsczymm1015/xiaomi_watch_s5-relay/releases/download/v0.2.0/xiaomi-watch-relay.zip)（解压后安装），也可[直接下载 APK](https://github.com/jsczymm1015/xiaomi_watch_s5-relay/releases/download/v0.2.0/xiaomi-watch-relay.apk)，准备已通过小米运动健康绑定的手表。首次启动按系统提示授予蓝牙／附近设备权限；Android 11 及以下扫描还可能要求定位权限。

## 导入连接信息

1. 先让小米运动健康正常连接并同步手表。
2. 如果当前运动健康版本提供导出入口，可在“我的 → 关于”连续点击顶部 App 图标约 10 次，再按提示导出日志。入口和内容会随版本改变，并非所有版本都提供有效连接字段。
3. 回到中转 App，点击“导入连接信息”，通过系统文件选择器选择自己手机中最新导出的日志 ZIP／文本。常见位置是 `Download/wearablelog`；以手机实际导出位置为准。
4. 确认界面显示导入成功，再搜索、选择自己的手表。

已配对与搜索列表仅显示名称含 `Watch` 的设备（忽略大小写）；名称不同的设备不显示，出现在列表中并不意味着已通过 Q63 身份验证。

导入器只提取已识别的手表认证字段，不将任意账号 token 当作认证密钥。包含多个不同设备密钥、缺少有效字段或超出解析上限时会拒绝导入，不盲选。原日志可能含个人信息，**保留在自己的手机，不上传 GitHub、不发送给开发者**。无需自行查看或粘贴密钥；已有密钥的高级入口仍受相同认证与目标型号校验约束。

日志流式解析，不解压到磁盘、不保存原日志副本。最大输入 32MB、单 ZIP 条目解压 16MB、总解压 64MB、最多 256 条目。运行中的认证信息在取消／页面销毁时清除；更新 App 结束旧进程后，需要重新本地导入。绑定未改变时可使用原先有效的本地日志。

## 手动导入并应用 R14

0.2.0 APK 默认内置 R13（`941006213`），本次没有重建 APK。新版独立表盘为 R14（`941006214`）：下载 [l1d-rain-r14.face](https://github.com/jsczymm1015/xiaomi_watch_s5-relay/releases/latest/download/l1d-rain-r14.face)，也可下载 [仓库中的 R14 文件](../faces/l1d-rain-r14.face)，必须通过“选择表盘文件”手动导入。最新 `r14` Release 只发布表盘及说明，App 仍从 `v0.2.0` 下载。需要旧版时，可从 [v0.2.0 的 R13](https://github.com/jsczymm1015/xiaomi_watch_s5-relay/releases/download/v0.2.0/l1d-rain-r13.face) 下载。

R14 仅将熄屏 Q 版人物面向观看者右侧的腿（人物左腿）改为白色过膝袜；亮屏动态与排版沿用 R13，不包含压力条件动画。R14 尚未真机安装。

1. 在中转 App 选择自己的手表，点击“选择表盘文件”选中 `l1d-rain-r14.face`，在文件详情确认 ID 为 `941006214`。
2. 点击“连接、安装并应用”，先尝试已有绑定连接。
3. 如果连接失败，检查手表距离和手机蓝牙状态。运动健康可能占用连接，可暂时关闭其连接后重试。**只有失败后确有手表提示时，才进入手表的“连接新手机”页面；同一台手机不必默认重新绑定。** 按手机及手表系统提示确认，不恢复出厂。
4. 传输过程中保持 App 前台，等待进度与手表确认，不重复点击安装。连接错误、空间不足、电量不足或 ID 冲突时，以界面显示的具体阶段和手表响应为准。
5. 成功需要三个证据：手表确认已安装、确认已应用，以及列表回读显示该 ID 为当前表盘。只显示“传输完成”不足以证明应用成功。

蓝牙列表中的设备名不作为型号证明，连接后还会核对 Q63 或已知精确型号。明确冲突的产品代号、泛称“Watch S5”和缺少身份信息不会获准写入。

## 常见问题

| 现象 | 说明与处理 |
| --- | --- |
| 同一手机为什么会出现“连接新手机” | 中转 App 使用自己的蓝牙会话，系统配对与应用层认证是不同阶段。先尝试现有绑定；该页面只在确有连接失败和手表提示时使用。 |
| 已经扫描到手表，仍认证失败 | 扫描只证明设备可被发现。写入 `.face` 还需有效的本机连接信息；导入其他设备或旧绑定的日志不能代替认证。 |
| `read failed ... read ret:-1` | 表示蓝牙 socket 被关闭或超时，不单独证明密钥错误。App 先尝试标准兼容 RFCOMM，再尝试配对通道；检查距离、连接占用及手表提示。 |
| 传输较慢 | R14 与 R13 原始文件均约 25.32MiB；实际传输受蓝牙吞吐、分片确认、重传和手表写入速度影响。60Hz 屏幕刷新率与蓝牙吞吐无关。 |
| 手机上没有日志导出入口／导入失败 | 当前运动健康版本可能没有该入口或认证字段。App 会明确失败；不绕过认证，也不读取其他 App 的私有目录。 |
| 只想用运动健康导入原生 `.face` | 相册自定义与原生动态表盘导入不是同一流程。本工具提供独立的本地导入、认证和传输流程。 |
| 预览压力变化没有触发角色状态 | 当前 R13／R14 均不支持压力条件动画。网页模拟不代表 Q63 固件支持；详见 [格式限制](FORMAT_LIMITS.md)。 |

R14／R13 截图里的时间、电量和指标均为演示值。安装确认不证明动态帧率、健康字段含义、农历闰月或熄屏效果；这些要在手表上分别核对。
